2. Database: Create And Use

Definition

A database is a container where tables and data are stored. Think of it like a folder. Inside that folder, we keep tables like Employee, Bonus, Books, and City.

Why We Use It

We create a separate database so our learning tables stay in one place and do not mix with other project data.

Example

CREATE DATABASE MyLearningDB;

USE MyLearningDB;

Explanation

CREATE DATABASE MyLearningDB creates a new database. USE MyLearningDB tells SQL Server: "Run the next queries inside this database."

3. OBJECT_ID And DROP TABLE

Definition

OBJECT_ID checks whether a database object exists. A table is also a database object. DROP TABLE deletes a table completely.

Why We Use It

If you run CREATE TABLE Employee again when the table already exists, SQL Server gives an error. So first we check and drop the old table.

Example

IF OBJECT_ID('dbo.Employee', 'U') IS NOT NULL
BEGIN
    DROP TABLE Employee;
END
GO

Explanation

  • dbo.Employee means the Employee table under the dbo schema.
  • 'U' means user table.
  • If the table exists, SQL Server drops it.
  • GO tells SQL Server Management Studio to finish this batch and start a new one.
Careful: DROP TABLE removes the table and all data inside it. Use it only when you really want to recreate the table.

4. Create Table Employee

Definition

CREATE TABLE creates a new table. A table is like an Excel sheet. It has columns and rows.

Why We Use It

We need the Employee table to store employee details like employee id, name, email, manager id, salary, and status.

Example

CREATE TABLE Employee
(
    EmpId Varchar(10) Primary Key,
    Fullname Varchar(100),
    EmailId Varchar(100) Unique,
    ManagerId Varchar(10),
    Salary Decimal,
    Status Int
);

Column Explanation

ColumnMeaning
EmpIdEmployee id. It is the primary key, so every employee must have a unique id.
FullnameEmployee full name.
EmailIdEmployee email. It is unique, so two employees cannot have the same email.
ManagerIdThe employee id of the manager. It can be null for top-level manager.
SalaryEmployee salary.
StatusUsually used to show active or inactive. Here, 1 means active.

5. Primary Key And Unique Key

Definition

A primary key uniquely identifies each row in a table. A unique key also prevents duplicate values in a column.

Why We Use It

We use keys to keep data clean. For example, two employees should not have the same EmpId, and two employees should not use the same email id.

Example From Employee Table

EmpId Varchar(10) Primary Key,
EmailId Varchar(100) Unique

Explanation

  • Primary Key does not allow duplicate values.
  • Primary Key does not allow null values.
  • Unique does not allow duplicate values.
  • A table can have only one primary key, but it can have multiple unique keys.

7. SELECT Query

Definition

SELECT is used to read data from a table.

Why We Use It

We use it when we want to see all rows or specific columns from a table.

Example

SELECT * FROM Employee;

Explanation

* means all columns. This query shows every row and every column from the Employee table.

8. Self Join: Employee And Manager In Same Table

Definition

A self join means joining a table with itself. We use the same table two times with different names.

Why We Use It

In the Employee table, employee and manager are both employees. Manager details are also stored in the same table. So we join Employee with Employee.

Example

SELECT
    e.EmpId,
    e.Fullname,
    e.EmailId,
    e.Salary,
    m.EmpId AS ManagerId,
    m.Fullname AS ManagerName
FROM Employee e
LEFT JOIN Employee m
    ON e.ManagerId = m.EmpId;

Explanation

  • e means employee.
  • m means manager.
  • e.ManagerId = m.EmpId connects employee to manager.
  • LEFT JOIN keeps all employees, even if manager details are not found.

Simple Example

If Shraddha's ManagerId is EMP101, SQL Server looks for employee EMP101 and shows that person's name as Shraddha's manager.

9. LEFT JOIN

Definition

LEFT JOIN returns all rows from the left table and matching rows from the right table.

Why We Use It Here

Some employees may not have a manager. If we use inner join, those employees may disappear from the result. With left join, they still appear.

What Happens

If manager is found, manager details are shown. If manager is not found, manager columns show NULL.

10. Window Functions

Definition

Window functions calculate a value across rows while still keeping each row visible. They do not group rows into one row like normal aggregate queries.

Why We Use Them

We use window functions when we want serial numbers, ranking, top salary, second highest salary, or row-wise calculations.

Important Syntax

FUNCTION_NAME() OVER (ORDER BY column_name)

Explanation

OVER tells SQL Server how to arrange or divide rows before applying the window function.

11. ROW_NUMBER()

Definition

ROW_NUMBER() gives a unique running number to each row.

Why We Use It

We use it when we need a serial number or when we want to identify duplicate rows.

Example

SELECT ROW_NUMBER() OVER (ORDER BY EmpId) AS Sno, *
FROM Employee;

Explanation

Rows are ordered by EmpId. SQL Server then gives serial numbers: 1, 2, 3, 4, 5.

Important Point

ROW_NUMBER() never gives the same number to two rows, even if salary or other values are the same.

12. RANK()

Definition

RANK() gives rank based on the order. If duplicate values exist, it gives the same rank and skips the next rank number.

Why We Use It

We use RANK() when we want competition-style ranking.

Example

SELECT RANK() OVER (ORDER BY Salary) AS Rank, *
FROM Employee;

Explanation

If three employees have salary 10000, all three get the same rank. The next rank is skipped based on how many rows already used that rank.

Simple Ranking Example

13. DENSE_RANK()

Definition

DENSE_RANK() gives the same rank for duplicate values, but it does not skip rank numbers.

Why We Use It

We use it when we want clean ranking without gaps. It is useful for finding highest salary, second highest salary, third highest salary, and so on.

Example

SELECT DENSE_RANK() OVER (ORDER BY Salary DESC) AS Rank, *
FROM Employee;

Explanation

ORDER BY Salary DESC means highest salary comes first. The highest salary gets rank 1.

Simple Ranking Example

15. CTE: Common Table Expression

Definition

CTE means Common Table Expression. It is a temporary named result set used inside one query.

Why We Use It

We use CTE to make complex queries easier to read. In your script, CTE is used to calculate rank first, then filter by rank.

Example

;WITH cte_sal_data AS
(
    SELECT DENSE_RANK() OVER (ORDER BY Salary DESC) AS Rank, *
    FROM Employee
)
SELECT *
FROM cte_sal_data
WHERE Rank = 1;

Explanation

  • The CTE name is cte_sal_data.
  • Inside the CTE, employees are ranked by salary.
  • Outside the CTE, we select only Rank = 1.
  • This gives the employee or employees with the highest salary.
The semicolon before WITH is used because SQL Server expects the previous statement to be ended before starting a CTE.

16. Bonus Table And Identity Column

Definition

IDENTITY(1,1) automatically generates numbers. The first value is 1, and it increases by 1 for each new row.

Why We Use It

We use identity columns when we do not want to manually type ids.

Example

CREATE TABLE Bonus
(
    BonusId Int Primary Key Identity(1,1),
    Item Varchar(100),
    Status Int
);

INSERT INTO Bonus VALUES
('Smart Watch', 1),
('Sweet Box', 1);

Explanation

You insert only Item and Status. SQL Server automatically fills BonusId as 1, 2, and so on.

17. CROSS JOIN And Cartesian Product

Definition

CROSS JOIN combines every row from the first table with every row from the second table. This is called a Cartesian product.

Why We Use It

We use cross join when we want all possible combinations.

Example

SELECT
    e.EmpId,
    e.Fullname,
    e.EmailId,
    b.Item
FROM Employee e
CROSS JOIN Bonus b
ORDER BY e.Fullname;

Explanation

If there are 5 employees and 2 bonus items, the result will have 10 rows. Each employee is matched with each bonus item.

Formula

Total rows = number of Employee rows * number of Bonus rows
Total rows = 5 * 2 = 10
Be careful with cross join. If one table has 1,000 rows and another table has 1,000 rows, the result will be 1,000,000 rows.

19. PARTITION BY

Definition

PARTITION BY divides rows into groups for a window function.

Why We Use It

To find duplicate books, we group rows by bookname and author. Inside each group, we give row numbers.

Example

SELECT ROW_NUMBER() OVER
(
    PARTITION BY bookname, author
    ORDER BY BookId
) AS Sno, *
FROM books;

Explanation

If the same book and author appear 3 times, they are treated as one group. The first row gets Sno = 1, second gets Sno = 2, third gets Sno = 3.

20. Remove Duplicate Records Using CTE

Definition

We can remove duplicates by keeping the first row and deleting the remaining duplicate rows.

Why We Use CTE Here

The CTE makes it easy to first mark duplicates using row number and then delete rows where row number is greater than 1.

Example

;WITH cte_dup_books AS
(
    SELECT ROW_NUMBER() OVER
    (
        PARTITION BY bookname, author
        ORDER BY BookId
    ) AS Sno, *
    FROM books
)
DELETE FROM cte_dup_books
WHERE Sno > 1;

Explanation

  • Sno = 1 means first copy. We keep it.
  • Sno > 1 means duplicate copy. We delete it.
  • After delete, only one record remains for each book and author combination.
In real work, always run the SELECT version first before DELETE, so you can see what will be deleted.

21. Index In SQL Server

Definition

An index helps SQL Server find data faster. It is like the index page or table of contents in a book.

Why We Use It

Without an index, SQL Server may scan the whole table to find matching rows. With a good index, SQL Server can go directly to the matching data faster.

Simple Example

If you want to find "Bangalore" in a city table, SQL Server can search faster if there is an index on cityname.

22. Clustered Index

Definition

A clustered index decides the physical order of data rows in a table.

Why We Use It

It helps SQL Server find rows faster when searching by the clustered key.

Important Points

  • Only one clustered index is allowed for a table.
  • A primary key usually creates a clustered index by default.
  • The real table data is organized based on the clustered index.

Example

CREATE TABLE city1
(
    cityid Int Primary Key,
    cityname Varchar(10)
);

Explanation

Here cityid is primary key. SQL Server usually creates a clustered index on it unless told otherwise.

23. Heap Table: Table Without Clustered Index

Definition

A heap table is a table without a clustered index.

Why It Matters

When there is no useful index, SQL Server may need to scan the whole table to find data.

Example

CREATE TABLE city
(
    cityid Int,
    cityname Varchar(10)
);

Explanation

This table has no primary key and no clustered index. So the data is not organized by a clustered key.

24. Nonclustered Index

Definition

A nonclustered index is a separate structure that points to the actual table rows.

Why We Use It

We use it to speed up searches on columns that are used often in WHERE, JOIN, or ORDER BY.

Example

CREATE NONCLUSTERED INDEX cl_city_index
ON City1(cityname);

Explanation

This creates a nonclustered index on cityname. Now searching by city name can become faster.

25. Table Scan Vs Index Seek

Definition

A table scan means SQL Server reads many rows or the full table. An index seek means SQL Server uses an index to directly find the matching rows.

Why It Matters

Index seek is usually faster for searching specific values, especially when the table has many rows.

Example Without Useful Index

SELECT *
FROM city
WHERE cityname = 'bangalore';

Example With Nonclustered Index

SELECT *
FROM city1
WHERE cityname = 'bangalore';

Explanation

The city table has no index on city name, so SQL Server may scan the table. The city1 table has a nonclustered index on city name, so SQL Server can use the index to search faster.

26. SET STATISTICS TIME

Definition

SET STATISTICS TIME ON shows how much CPU time and elapsed time SQL Server used for a query.

Why We Use It

We use it to compare query performance. For example, we can compare a table scan query and an indexed query.

Example

SET STATISTICS TIME ON;

SELECT *
FROM city1
WHERE cityname = 'bangalore';

SET STATISTICS TIME OFF;

Explanation

After running the query, SQL Server shows timing information in the Messages tab in SSMS. Lower time usually means better performance.
