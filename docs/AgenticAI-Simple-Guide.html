1. What Is Agentic AI?

Agentic AI means AI that can do a job step by step.

A normal chatbot mostly gives text answers. An agentic AI can also use tools. For example, it can check a database, read a file, call an API, search a system, or run a small workflow.

Simple example:

You ask: "How many gold customers do we have?" A normal chatbot may guess. An Agentic AI says: 1. I need real customer data. 2. I will check the database. 3. I will run a safe SQL query. 4. I will read the result. 5. I will answer the user in simple words.

So the short meaning is:

Agentic AI = AI brain + tools + step-by-step loop + safety rules.

2. Normal AI vs Agentic AI

Normal AI Agentic AI
Mostly talks and answers from what it already knows. Can talk and also take actions using tools.
May guess when it does not have data. Can go and fetch data before answering.
Usually one question gives one answer. Works in steps until the job is done.
Cannot safely query your SQL Server by itself. Can ask the app to run a safe read-only SQL query.

3. Easy Real-Life Example

Imagine you ask a human assistant:

"Please tell me total sales for this month."

A good assistant will not guess. They will open the sales system, check the numbers, and then tell you the answer.

Agentic AI works in a similar way:

  1. Understand the request.
  2. Decide what information is needed.
  3. Use a tool to get that information.
  4. Check the result.
  5. Answer in clear language.

4. Main Parts Of Agentic AI

Part 1: Brain

The brain is the AI model. Examples are Google Gemini, ChatGPT, Claude, and other LLMs. LLM means Large Language Model. It reads text and decides what to do next.

Part 2: Tools

Tools are things the AI can use. In this demo, the main tool is SQL Server. The AI does not directly touch the database. It asks our C# app to run a safe query.

Part 3: Memory

Memory means remembering what happened before. In our demo, the agent remembers previous steps in the same question. For example, it remembers what SQL query ran and what result came back.

Part 4: Planning

Planning means breaking the work into small steps. The agent thinks: "Do I need data? Which table should I use? Do I have enough information to answer?"

Part 5: Safety Rules

Safety rules stop the agent from doing dangerous things. Our demo only allows SELECT queries. That means the agent can read data, but it cannot delete, update, create, or drop anything.

5. How Agentic AI Works: The Loop

The most important idea is the loop. The loop is also called the ReAct pattern. ReAct means Reason + Act.

1. Perceive -> Read the user's question 2. Reason -> Think about the next useful step 3. Act -> Use a tool, like SQL Server 4. Observe -> Read the tool result 5. Repeat -> Continue until answer is ready or max steps are reached

Example:

User: "How many customers do we have?" Step 1: Thought: I need to count customers from the Customers table. Action: run_sql Input: SELECT COUNT(*) AS TotalCustomers FROM Customers Observation: TotalCustomers = 8 Step 2: Thought: I have the number now. Action: answer_user Input: You have 8 customers.

6. What Happens When The User Sends A Request?

Here is the full journey in the AgenticAIDemo app.

  1. The user types a question in the console.
  2. Program.cs reads appsettings.json.
  3. The app loads the Gemini API key, model name, SQL Server connection string, and agent rules.
  4. The app checks if SQL Server is reachable.
  5. If SQL Server is working, the app creates the services.
  6. The app decides which brain to use: Gemini or Local Fallback.
  7. AgentService starts the loop.
  8. The brain chooses one action: run_sql or answer_user.
  9. If action is run_sql, SqlServerService runs a safe SELECT query.
  10. The SQL result is sent back to the brain.
  11. When the brain has enough information, it sends the final answer.
  12. The console prints all steps and the final answer.

7. What Happens When Data Is Not Available Locally?

This is very important because real AI apps must be honest when data is missing.

Case 1: Gemini API key is not available

The app uses Local Fallback mode if UseLocalFallback is true.

  • It does not call Google Gemini.
  • It does not need internet.
  • It uses simple keyword rules.
  • It still queries your local SQL Server.
  • It is less smart, but useful for learning.

Case 2: SQL Server is not running

The app stops at startup. It tells you to start SQL Server, run the setup SQL script, and check the connection string.

Case 3: Database tables are missing

The app may connect to SQL Server, but it cannot find the expected Customers and Orders tables. You must run Scripts/SetupDatabase.sql.

Case 4: User asks for data that does not exist

Example: the user asks for Platinum customers, but the database has only Gold, Silver, and Bronze customers.

The query may return no rows. The correct answer is: "No matching data was found." The agent should not invent fake data.

Case 5: Internet is not available

If Gemini is selected but internet is down, the Gemini API call fails. The local database may still be fine. To continue learning, use Local Fallback mode.

Case 6: Local Fallback does not understand the question

Local Fallback is simple. It looks for words like "gold", "sales", "city", "order", and "how many customers". If your question is complex, Gemini mode works better.

8. What Is RAG?

RAG means Retrieval-Augmented Generation.

Simple meaning:

First fetch real information. Then ask AI to answer using that information.

In this demo, SQL Server is the place where real information lives. The agent gets real rows from SQL Server before answering. This reduces guessing.

9. What Is An API Key?

An API key is like a password for your app. It lets your C# app call Google Gemini.

  1. Go to Google AI Studio.
  2. Create or copy an API key.
  3. Paste it into appsettings.json.
  4. Keep it private.
Important: Do not share your real API key. Do not put real keys or database passwords in public GitHub code.

10. What The Demo App Does

AgenticAIDemo is a C# console app. It lets you ask normal English questions about a small shop database.

The database has two main tables:

  • Customers: customer name, city, and membership level.
  • Orders: products, amount, order date, and related customer.

Example questions:

  • How many customers do we have?
  • Who are our gold members?

public sealed record AgentStep
{
    public int StepNumber { get; init; }
    public string Thought { get; init; } = string.Empty;
    public string? Action { get; init; }
    public string? ActionInput { get; init; }
    public string? Observation { get; init; }
}

{
    public string FinalAnswer { get; init; } = string.Empty;
    public List<AgentStep> Steps { get; init; } = [];
    public bool UsedDatabase { get; init; }

{
    public string Thought { get; init; } = string.Empty;
    public string Action { get; init; } = "answer_user";

Step 6: Create Services

Create a folder named Services. Services are classes that do actual work.

Service fileSimple job
SqlServerService.csConnects to SQL Server, reads schema, and runs safe SELECT queries.
GeminiService.csSends the question and previous steps to Google Gemini.
LocalFallbackService.csBackup brain when there is no Gemini API key.
AgentService.csThe main boss. Runs the agent loop.

Step 7: Build SqlServerService.cs

This service is the database tool.

  • TestConnectionAsync checks if SQL Server is reachable.
  • GetSchemaDescriptionAsync tells the AI what tables and columns exist.
  • ExecuteSafeQueryAsync runs a query and returns the rows as text.
  • IsReadOnlySelectQuery blocks unsafe SQL.

Safety rule:

Only SELECT queries are allowed.
INSERT, UPDATE, DELETE, DROP, ALTER, CREATE, EXEC, and similar commands are blocked.

Step 8: Build GeminiService.cs

This service is the online AI brain.

  • It creates a prompt for Gemini.
  • It includes the user question.
  • It includes the database schema.
  • It includes previous agent steps.
  • It asks Gemini to return strict JSON.

Gemini must choose one of these actions:

{
  "thought": "what the AI is thinking",
  "action": "run_sql or answer_user",
  "actionInput": "SQL query or final answer"
}

Step 9: Build LocalFallbackService.cs

This service is a simple offline brain.

  • If the question contains "gold", it queries gold customers.
  • If the question contains "sales" or "total", it queries total sales.
  • If the question contains "city", it groups customers by city.
  • If the question contains "order", it shows recent orders.
  • If it does not understand, it runs a general sample query.

This is not as intelligent as Gemini, but it helps you understand the agent loop without internet.

Step 10: Build AgentService.cs

This is the heart of the app. It runs the ReAct loop.

For each step from 1 to MaxSteps: 1. Ask Gemini or Local Fallback: What should we do next? 2. If action is run_sql: Run SQL using SqlServerService. Save the result as observation. Continue the loop. 3. If action is answer_user: Save final answer. Stop the loop. 4. If action is unknown: Stop safely. If max steps are reached: Tell the user to try a simpler question.

Step 13: Create Program.cs

Program.cs is the entry point. It is the first file that runs.

It does these jobs:

  1. Prints the welcome message.
  2. Loads appsettings.json.
  3. Creates SqlServerService.
  4. Tests the database connection.
  5. Creates GeminiService if API key is available.
  6. Creates LocalFallbackService.
  7. Creates AgentService.
  8. Starts a chat loop.
  9. Handles commands like help, schema, and exit.
  10. Prints every agent step and final answer.

Simple flow:

Start app Load settings Connect to SQL Server Choose Gemini or Local Fallback Create AgentService Ask user for a question Run agent Print steps Print final answer Repeat until user types exit

14. Safety Rules In This Demo

Safety ruleWhy it matters
Only SELECT SQLThe agent can read data but cannot change or delete data.
MaxSteps = 5The loop stops after 5 steps, so it does not run forever.

15. Simple Interview Answers

Question: What is Agentic AI?

Agentic AI is AI that can work step by step. It understands the goal, plans the next step, uses tools like databases or APIs, checks the result, and then gives an answer.

Question: How is it different from a normal chatbot?

A normal chatbot mostly talks. An agentic AI can talk and also act. For example, it can query SQL Server and answer using real data.

Question: What is tool use?

Tool use means the AI asks the app to do something useful, like run a SQL query. The AI decides the action, but the app performs it safely.

Question: Why do we need guardrails?

Guardrails keep the AI safe. In this demo, the agent can only run SELECT queries, so it cannot delete or update data.

Question: What happens if the data is missing?

The agent should not guess. It should say that no matching data was found, or tell the user what setup is missing.
